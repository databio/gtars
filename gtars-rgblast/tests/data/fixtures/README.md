# Test fixtures

Generated by `make_fixtures.py` (deterministic: run it here to reproduce every file). Each test
binary builds a fixture store from them with the gtars-refget API (`tests/common/store.rs`), once
per storage mode (Encoded, Raw, Zstd): one collection per FASTA, registered as `name:<asm>`, plus
the aliases in `aliases.tsv`, the FHR sidecar `asmA.fhr.json`, and `orphan.fa` ingested with no
collection.

| Case | Fixture |
|---|---|
| 2-bit, lengths with `len % 4` = 0, 1, 2, 3 | `asmA.fa` `chr1` (1,000 bp); `asmB.fa` `chrB1`/`chrB2`/`chrB3` (1,001/1,002/1,003 bp) |
| N runs of 1, 15, 16, 4,095, 4,096 and 4,097 (old and new ambiguity formats, the 4,095 run split) | `asmA` `chr2` (3-bit, 12,670 bp) |
| R, Y, U (U is stored as T by BLAST) | `asmA` `chrM` (3-bit) |
| full IUPAC M K S W B D H V | `asmA` `iupac1` (4-bit) |
| `\|` and `;` sanitizing | `asmA` `ENA\|KI270740\|KI270740.1` (with a description) and `chrX;alt` |
| `:` and `*` in names | `asmA` `HLA-A*01:01:01:01` |
| numeric-tag edge values | `numeric.fa`: `0`, `1`, `22`, `00`, `007`, `0012`, `2147483647`, `2147483648`, `4294967296`, `+1`, `-1` |
| shared sequence, same name / different name | `asmB` `chr1` = `asmA` `chr1`; `asmB` `chrUn_x` = `asmA` `chr2` |
| two aliases in one namespace; aliases in two namespaces | `asmC`: `name:asmC`, `name:asmC-alt`, `refseq:GCF_TEST.1` |
| collection digest starting with `-` | `asmD.fa`: one name, `dash36`, found by the search loop in `make_fixtures.py`; collection digest `-mUDCQQpL9DEJNAWJwKUihDtm1yGTnoP` |
| protein sequence skipped | `asmC` `prot1` (59 aa) |
| orphan sequence | `orphan.fa`, ingested with no collection |
| sequence aliases, including all-digit and leading-zero ones | `aliases.tsv`: `insdc:CM000001.1`, `refseq:NC_TEST.1` (asmA chr1), `insdc:123456` (asmA chrM), `insdc:0099` (asmB chrB1) |
| sanitizing collision | `collide.fa` (`a\|b` and `a_b`), its own store |
| alias string reused across namespaces for different collections | built in the test (`name:X` -> asmA, `ucsc:X` -> asmB) |

The long ambiguity format (sequences longer than 0xFFFFFF bp) and the oversize path are covered
in memory by unit and functional tests, not with stored fixtures.

`../expected/plan_fixture.tsv` is the canonical OID order, ids and titles of the whole fixture
store (`oid_order_is_canonical`). Its first line is the `SUBJECT_PLAN_VERSION` it was made with;
a deliberate change updates the file (`GTARS_RGBLAST_UPDATE_EXPECTED=1 cargo test -p
gtars-rgblast --test functional oid_order`) and bumps the constant in the same commit.

## `txome` (many short sequences)

Not committed as FASTA: `tests/common/txome.rs` generates it at test time from a fixed seed and
builds it once per storage mode (`txome(mode)`); `txome.expected.json` pins the md5 and record
count of every generated FASTA and the totals of a whole-store plan (`txome_fixture_matches_expected`;
regenerate with `GTARS_RGBLAST_UPDATE_EXPECTED=1 cargo test -p gtars-rgblast --test txome`).

| Collection | Contents |
|---|---|
| `txome_a` | 1,500 transcripts of 150–4,000 bp; 3 % with an N run, 1 % with IUPAC codes, 1 % repeating an earlier sequence under a new name; 30 isoform groups of 3–25 transcripts sharing one 300-bp exon |
| `txome_b` | 800 transcripts; 300 share a sequence with `txome_a` (half under the same name) |
| `bin01`…`bin40` | 10–30 contigs of 500–20,000 bp each (named `<bin>_k141_<n>`, so `-taxid_map` can express the taxa), FHR taxid 100000 + 7 × (n − 1) |

`TxomeSpec::many_bins(n)` writes `n` tiny bins whose contig names repeat across bins, and nothing else, for the thousands-of-collections
tests (`many_collections_reduced`, 200; `many_collections_full`, 2,000, ignored).
